# Итоговый отчёт

Self-hosted картографический сервис для одного города (Астана) на OSM: векторные тайлы, геокодинг, автодополнение и маршруты за API-шлюзом на Go. Документация по использованию — в [README](../README.md), контракт API — в [api/openapi.yaml](../api/openapi.yaml).

## 1. Что сделано

| Этап | Результат |
|---|---|
| 1. Исследование | Актуальные версии всех компонентов проверены по реестрам и закреплены (таблица в README). Выяснено: Photon 1.x — Java 21+, OpenSearch 3.x встроен в jar, импорт из Nominatim — подкоманда `import`, официального образа нет; tilemaker пишет PMTiles напрямую; у OSRM теги `vX.Y.Z-debian`; у tilemaker в ghcr только тег `master`. |
| 2. Данные и compose | `deploy/docker-compose.yml` (+ dev-оверлей, Caddyfile, Dockerfile Photon/gateway/updater); пайплайн `download → extract → osrm → tiles → nominatim → photon`. Все upstream поднимаются и отвечают напрямую. |
| 3. Gateway | Клиенты OSRM/Nominatim/Photon на `net/http`; эндпоинты API v1; auth, rate limit, CORS, request-id, recovery, JSON-логи; кэш Redis; graceful shutdown; таймауты. |
| 4. Тайлы | PMTiles через встроенный go-pmtiles; стиль OSM Liberty (адаптирован), глифы Noto Sans, спрайты, `preview.html`; генератор `cmd/stylegen`. |
| 5. Updater | Smoke-тесты, переключение с откатом, очистка версий, расписание (cron), блокировка параллельных запусков. |
| 6. Тесты и документы | 229 unit-тестов, 11 интеграционных, lint без замечаний, README, OpenAPI, этот отчёт. |

Структура репозитория соответствует заданию; добавлено сверх него: `internal/geo`, `internal/dataset`, `internal/stylegen`, `cmd/stylegen`, `test/repo`, `.golangci.yml`, `docs/`.

## 2. Проверка по критериям приёмки

Проверялось на Docker Desktop 4.16 (движок 20.10.22, linux/arm64, 5 CPU / 8 ГБ) на реальном файле Казахстана от 13.10.2026.

| № | Критерий | Результат |
|---|---|---|
| 1 | `cp .env.example .env` → правка → `make init-data && make up` без ручных шагов | **Выполнено** с чистого листа (данных и томов нет, свежий `.env`): 3 мин 20 с, дальше `readyz` 200. Не проверялось: настоящий «чистый сервер» с нуля (образы уже были скачаны) и выпуск сертификата Let's Encrypt. |
| 2 | `/readyz` = 200, все upstream ok | **Выполнено**: nominatim, photon, osrm-car, osrm-foot, tiles, redis — `ok`. |
| 3 | Все эндпоинты по контракту, ошибки в едином формате | **Выполнено**: 11 интеграционных тестов на живом стеке через Caddy + unit-тесты. |
| 4 | Карта открывается в MapLibre (`preview.html`) | **Выполнено**: открыта во встроенном браузере — подписи кириллицей, переключение `ru/kk/en`, консоль чистая, все запросы только к самому gateway. |
| 5 | `make update-data` без простоя; при сломанном шаге живая версия работает | **Выполнено с оговоркой.** Фаза сборки (≈ 4 мин) ошибок не давала; сломанный поздний шаг (smoke) за 3 мин и 1267 запросов зонда дал **0 неуспешных**, живые сервисы не перезапускались, лишнего не осталось. Откат при сбое `release` проверен вживую. **Само переключение — скользящий перезапуск**: ≈ 2–7 с `502` на геокод/reverse и ≤ ≈ 1 с на маршрут; тайлы и автодополнение — без ошибок. |
| 6 | `make test`, `make test-integration`, `make lint` проходят | **Выполнено** (lint: 0 issues). |
| 7 | RAM всего стека в простое < 8 ГБ | **Выполнено**: ≈ 0,7–1,0 ГиБ. Пик при обновлении ≈ 4,5 ГиБ (из них 3,5 ГиБ — `osmium extract`). |

Дополнительно проверено вживую: хранение двух версий (`DATA_KEEP_VERSIONS=2`), удаление старых версий и их томов, режим `polygon`, работа планировщика (срабатывание по расписанию, переживание сбоя, следующий запуск), отсутствие публикуемых портов у всего, кроме Caddy.

## 3. Решения, принятые самостоятельно

1. **Updater в контейнере с docker.sock** и инструменты как сервисы compose профиля `tools`: все версии образов — в одном файле; обоснование — в README. Цена: доступ к сокету (описано в разделе безопасности).
2. **Версия данных = каталог `data/<UTC-метка>` + симлинк `data/current` + именованный том Nominatim на версию**. Это даёт атомарное переключение, откат и простую очистку.
3. **Переключение — скользящий перезапуск**, не blue/green (допускалось заданием). Gateway сам следит за симлинком, поэтому не перезапускается.
4. **smoke-тесты используют клиенты gateway** — заодно проверяют совместимость форматов upstream.
5. **Контейнер-кандидат Nominatim** становится живым после остановки (его том переиспользуется): импорт не повторяется.
6. **`osmium` собирается из закреплённых исходников** (в Alpine нет пакета, доверенных образов нет); strategy `smart` — целые мультиполигоны и границы на краю bbox.
7. **tilemaker закреплён по digest** (в ghcr только `master`); конфиг для города генерируется из шаблона с `bounding_box`; слои, требующие сторонних shapefile (`ocean`, `urban_areas`, `ice_shelf`, `glacier`), убраны.
8. **Стиль**: OSM Liberty с заменой Roboto на Noto Sans (OFL, нужны казахские буквы), подписи через `coalesce(name:<lang>, name:latin)` — иначе подписей не было бы, т. к. tilemaker не пишет `name`/`name_en`. Генерация воспроизводима (`make style-assets`, все источники — по sha256).
9. **Разбор query вручную**: `net/url` молча отбрасывает пары с `;`, а контракт требует `points=lon,lat;lon,lat`.
10. **Не кэшируется fallback на Nominatim, случившийся из-за сбоя Photon**; ошибки не кэшируются; для автодополнения в ключ добавлены `limit` и смещение (округлено до ≈ 1 км) — иначе пользователи из разных районов получали бы одинаковую выдачу.
11. **`readyz` не раскрывает внутренние детали**, Redis в нём информативен, но не делает сервис «неготовым».
12. **Сеть `internal: true`** — бэкенды физически не могут ходить в интернет.
13. **README и отчёт на русском**, OpenAPI и комментарии в коде — на английском.

## 4. Параметры, оставленные по умолчанию

Не заданы в задании и выбраны проектом (в `.env.example` помечены `[DEFAULT]`): `CITY_BBOX=71.04,50.74,71.96,51.46` (граница Астаны, relation 3087155, + ≈ 12 км), `CITY_CENTER`, `EXTRACT_STRATEGY=smart`, порядок `LANGUAGES=ru,kk,en`, лимиты запросов, `UPDATE_CRON=0 3 * * 0`, `DATA_KEEP_VERSIONS=2`, TTL кэша из задания, размеры памяти PostgreSQL/JVM/Redis под 8 ГБ, импорт Wikipedia выключен, `SITE_ADDRESS=:80`.

`OSM_SOURCE_URL` в задании — локальный файл `~/Downloads/kazakhstan-261013.osm.pbf`. В `.env.example` лежит боевое значение (Geofabrik); для проверки файл скопирован в `data/sources/` (контейнер updater не видит `~/Downloads`), в локальном `.env` указан путь к нему.

## 5. Отступления от задания

* Photon: вместо `-nominatim-import` — подкоманда `import` (так в версии 1.x).
* Версии закреплены тегами, кроме tilemaker (digest) и Photon (sha256 jar).
* Tilemaker-слои с внешними shapefile убраны; атрибуция OpenMapTiles добавлена (требование лицензии OSM Liberty).
* Добавлены пакеты и команда вне указанной структуры (см. п. 1).
* Blue/green не реализован (см. п. 3).

## 6. Известные ограничения

См. раздел в README. Главное: окно переключения (секунды на геокод/reverse), память `osmium extract` на больших странах, обновления по cron требуют доступа к Docker-сокету, не выполнялся прогон на Linux/amd64 и выпуск TLS-сертификата, Nominatim `reverse` может вернуть POI внутри здания.

## 7. Что бы я сделал дальше

* Два экземпляра Nominatim за алиасом (настоящий swap без простоя геокода).
* Prometheus-метрики gateway (go-pmtiles уже умеет) и дашборд.
* Двухступенчатая вырезка (регион → город) для стран, где `osmium extract` не помещается в память.
* Прогон приёмки на чистой Linux/amd64-машине с реальным доменом.
